# 入力資料の確認ルール

## PDF

- 表紙の講座名、版番号、対象者、講座時間を確認する。
- 目次と実際の章・スライド構成を照合する。
- 演習、ハンズオン、講師デモ、振り返りを区別する。
- プロンプト入力、ファイル操作、完成見本の確認など、受講生が操作する箇所を抽出する。
- PDF内の添付ファイル案内と、実際のワーク使用ファイルを照合する。
- 章番号、Act番号、スライド番号、製品名、モデル名、スペル、版番号の不一致を記録する。

## ワーク使用ファイル

- ファイル名だけでなく、確認可能な範囲で内容と用途を確認する。
- 現行PDFから参照されているかを確認する。
- プロンプトひな形、入力データ、完成サンプル、講師用ファイルを区別する。
- PDFに記載されているのに見つからないファイルと、PDFに記載されていない追加ファイルを記録する。

## 標準フォルダ構成

次の構成を標準として扱う。実際の構成が異なる場合は、勝手に移動せず差異を報告する。

~~~text
(root)
├ 受講生配布用PDF
├ ワーク使用ファイル
│  └ プロンプト雛形など
├ 講師共有ファイル
│  ├ スライドファイル
│  └ 講座概要.docx
└ OLD
~~~

`OLD`は過去資料の保管場所とし、現行資料の不足を埋めるために自動採用しない。

## 情報が食い違う場合

- ユーザーが最新条件を明示している場合は、その条件を優先する。
- 解消できない不一致は、講座概要の「注意点」に具体的な要確認事項として記載する。
- 不一致を解消したように見せるため、名称や数字を推測して統一しない。
